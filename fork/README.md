# fork/ — fork 管理文档目录

本目录**只放管理文档与登记表，不放产品代码**。

自有产品代码一律按"新文件"原则落到常规目录（规范见 `features/README.md`）：

- Rust 端点 → `src-tauri/src/web/handlers/<功能>.rs`（新文件）
- 前端组件 → `src/components/<功能>/`（新目录）
- API/类型 → `src/lib/api.ts`、`src/lib/types.ts` 只增不改

这样做是为了让上游合并永远只碰到我们没改过的文件。

## 索引

| 文档 | 什么时候看 |
| ---- | ---- |
| `patches/README.md` | 修后端 bug、提上游 PR、同步后处理补丁冲突前 |
| `features/README.md` | 加新功能（额度、雷达……）、裁剪上游功能前 |
| `frontend/README.md` | 改皮肤/布局/组件/动画等一切前端工作前 |

总纲（分支拓扑、同步 SOP、冲突速查）在根目录 `FORK.md`。

## 登记纪律

- 每加一个补丁 / 功能 / 裁剪，先登记再动工。
- 状态变化（PR 被收、功能完成、裁剪退役）及时回写登记表。
- 登记表是这个 fork 的"记忆"：三个月后没人记得哪个改动为什么存在，表记得。
